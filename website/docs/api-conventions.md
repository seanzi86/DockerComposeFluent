# API conventions

DockerComposeFluent follows a small set of conventions consistently across the whole API, so that once you've
learned one builder, the rest read the same way. The full write-up, with examples for every shape, is coming in
a follow-up to [issue #37](https://github.com/seanzi86/DockerComposeFluent/issues/37).

In the meantime, the source of truth is
[CONTRIBUTING.md](https://github.com/seanzi86/DockerComposeFluent/blob/main/CONTRIBUTING.md#api-design-conventions).
